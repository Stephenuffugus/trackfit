# Trackfit — 30/60/90 distribution plan

**Premise:** zero new features required. Everything below runs on what's
already shipped (v0.3.5). The goal is a clean read on one question: *will
this older, forum-based audience actually pay $19?* Spend nothing on paid
APIs until that reads yes.

The plan leans entirely on the one advantage a solo maker has over
AnyRail/SCARM/RailModeller: **you show up, you listen, you patch fast,
and you say so in public.** That loop is the strategy.

---

## Days 1–7 — go live, seed two forums

- [ ] Run `GO-LIVE-RUNBOOK.md` end to end. Confirm: live URL works on a
      phone, the $19 Founder modal shows a real buy link, a test purchase
      → code → activation round-trips.
- [ ] Post the **OGR** and **Model Train Forum** drafts
      (`forum-posts.md`). OGR first — it's the O-gauge/Lionel crowd the
      founder story lands hardest with. Space them a day apart.
- [ ] Be present. Reply to every response within 24h, plainly.
- **Watch:** Founder conversions, in-app pricing-feedback submissions,
      and every reported error. Keep a running log.

## Days 8–30 — close the loop in public, widen

- [ ] Fix the top reported issues fast. Each time, **reply in the
      original thread that it's fixed and live.** This visible
      maker-is-listening loop is the conversion engine for this
      demographic — protect time for it.
- [ ] Post the **MRH** and **Trains.com** drafts.
- [ ] Shoot and post the demo video (`demo-video-script.md`) into the
      live threads and as its own post. Captioned, calm, lead with the
      near-miss.
- [ ] If the library re-verification pass finishes, update the changelog
      and *then* you may make a measured accuracy statement — not before.
- **Decision gate at day 30:** any Founder sales + any genuine positive
  feedback → continue. Near-zero on both after two forums + a video →
  the validation answer is "not yet"; stop spending, reassess
  positioning rather than pushing harder.

## Days 31–60 — fund the next thing with revenue, not hope

- [ ] If Founder revenue exists, *now* it's defensible to flip real
      photo-ID on **for Founders only** (it's funded; the chicken/egg is
      broken). Watch per-photo cost vs. the budget gate.
- [ ] Email anyone who left an address in the pricing feedback with a
      short, personal "it's live, thanks for the input" — no blast, no
      template that reads like a CRM.
- [ ] Add the founder story as the site About page if it isn't already.
- [ ] Second-wave forum follow-ups only where there's an active thread —
      no re-posting into dead ones.

## Days 61–90 — decide what this is

- [ ] If conversion is real: consider raising the Founder price (existing
      Founders keep $19 — honor that publicly). Higher anchor, same model.
- [ ] Open exactly one B2B dataset conversation (`sell-sheet.md` §B2B) —
      inbound-style, low-key, not a sales push. Don't sell the moat cheap.
- [ ] Write the retro: what the forums actually said, conversion rate,
      cost per Founder (≈ your time), and the honest call — grow it,
      hold it as quiet income, or shelve it. Decide on data, not feel.

---

## Signals — what counts as "yes"

- **Strong:** unprompted "I'd pay for this" / actual Founder purchases /
  someone posts a layout they built using it.
- **Weak but real:** sustained error reports and feature asks (means
  people are *using* it enough to care).
- **Noise:** likes, "neat", view counts. Ignore.

## Guardrails (do not violate while distributing)

- No Reddit. No fake reviews/testimonials/numbers. No urgency gimmicks.
- No analytics/tracking added to chase this — the model is honest by
  design; keep it that way.
- No paid Vision spend before a revenue signal.
- No library accuracy claims before the re-verify pass lands.
- One post per forum; the value is the *responsiveness*, not the volume.
